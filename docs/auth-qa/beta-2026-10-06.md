## Reproduced and fixed

- Account A → B: an owner-key quota failure previously threw after B's cache had been restored, leaving B's data assigned to A. Ownership now commits while active storage is empty, before consuming B's cache. Failed restoration rolls ownership back before restoring A. If both restoration and ownership rollback fail, active data stays empty and both account snapshots survive. Returning to either account recovers its own snapshot. Regression cases reproduce the original exception and the double-failure recovery boundary.
- Corrupt preference journals previously accepted malformed backup/base/conflict payloads. Validation now rejects these before transport reads/writes or local imports, retaining the original recovery journal and local preferences. Four corruption cases cover invalid base values, missing/array backups and invalid conflict values. Existing verified-identity, first import, backup, idempotency, conflict, duplicate insert, offline retry and account-cancellation checks remain enabled.
- Hosted Auth had unassociated field labels, unnamed password visibility buttons and a signup commitment implemented as a clickable div. Inputs now have generated label targets, translated toggle names in all eight locales, native checkbox keyboard behavior, alert errors and busy forms.
- On `cfb5219`, a representative canonical confirmation callback (`?auth=confirmed&error=access_denied&error_code=otp_expired`) silently returned to entry. Callback error state now survives SDK initialization/null-session events and presents translated guidance, without reflecting URL descriptions or granting recovery authority. Unit cases cover both canonical actions, query/hash errors, normal codes, unrelated errors and malformed URLs.
